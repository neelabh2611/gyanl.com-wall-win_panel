How this cracks the original

🕵️ How we crack the original wall

1. Same open DB. This panel uses the exact firebase-config.js as gyanl.com/wall. The Realtime Database rules allow anyone to read/write wall/<index>, so we never touch the original site — we write straight to its database.

2. Bypass the UI. The original only lets you paint one square in your own colour. Here we call set / update directly on any path, with any { colour, name }, so Take DOUBLE / Take ALL can claim hundreds of squares in one multi-path update.

3. Guardian. onValue(wall) streams every change live. Guardian diffs names against yours every ~900ms + a 4s timer and re-paints lost squares, so you auto-reclaim #1.

4. Subpixels, zero server changes. A square's colour can be a conic-gradient (4 colours) / octant (8) / 64 / 256-colour string. The live page assigns it to style.background, so gradients render on the original as-is — photos, emoji, signs and movies without changing the server.

5. Volume tricks. Emoji/image raster to 64×36 then pack 2×2 blocks, video sends only changed squares (delta + 40MB/min budget guard), and verifyLive reads back wall.json and repairs any missing squares. That's why full pictures stick.
